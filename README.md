# jc — a small Java-to-JVM-bytecode compiler

The below information along with the entire project source code is written/generated by Claude Code.
The attempt was to check how compilers are developed/written and how to use Claude Code for the same.
Model used: Sonnet 5
Tokens used approximately: 120k

A hand-written compiler, in C++20, that takes a small subset of Java source
and produces a real `.class` file — runnable by any standard JVM, no custom
runtime required. Built as a learning project: every stage (lexer, parser,
semantic analysis, bytecode generation) is hand-written rather than
generated.

Only a deliberately small subset of Java is supported so far. See
[`docs/subset-v0.md`](docs/subset-v0.md) for exactly what's in and what's
still missing, and [`CLAUDE.md`](CLAUDE.md) for implementation status and
known limitations.

## Prerequisites

- A C++20 compiler (tested with AppleClang / Clang)
- CMake ≥ 3.20
- A JDK on your `PATH` (`java`, `javac`, `javap`) — not needed to build the
  compiler itself, but needed to *run* the `.class` files it produces, and
  to run the end-to-end test suite

```sh
# macOS, if cmake isn't installed:
brew install cmake
```

## Building

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j
```

This produces two binaries under `build/`:
- `compiler` — the CLI
- `compiler_tests` — the test suite

## Using the compiler

```sh
build/compiler <File.java> [-o outdir] [--dump-tokens] [--dump-ast]
```

- The source file's class name must match its filename (`Hello.java` must
  declare `class Hello`), same as `javac`.
- `-o outdir` — where to write `<ClassName>.class` (defaults to the current
  directory).
- `--dump-tokens` / `--dump-ast` — print the lexer/parser's intermediate
  output, useful for debugging.
- On any lex/parse/type error, diagnostics are printed as
  `file:line:col: error: ...` and the compiler exits non-zero without
  writing a `.class` file.

### Example

```sh
cat > Hello.java <<'EOF'
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, world!");
    }
}
EOF

build/compiler Hello.java
java Hello
# Hello, world!
```

More sample programs (arithmetic, loops, a class with fields/methods,
recursion) live in [`tests/programs/`](tests/programs/), each paired with
its expected output.

## Running the tests

```sh
cd build && ctest --output-on-failure
```

This runs both the unit tests (lexer, parser, semantic analysis) and an
end-to-end test that compiles every sample in `tests/programs/` and runs
the result on your real `java` binary, diffing stdout. If no `java` is
found on `PATH` at CMake configure time, the end-to-end test is compiled
out and the rest of the suite still runs.

## Project layout

```
src/
  lexer/    source text -> tokens
  ast/      AST node types + an S-expression pretty-printer
  parser/   tokens -> AST (recursive descent + precedence climbing)
  sema/     name resolution, type checking
  codegen/  AST -> constant pool + bytecode -> .class file
  driver/   the CLI (src/driver/main.cpp)
tests/
  unit/       lexer/parser/sema unit tests + the JVM-backed e2e test
  programs/   sample .java files with expected stdout
docs/
  subset-v0.md   exact language subset currently supported
```
